# 프롬프트 캐시 실측과 설계

> **이 문서의 수치는 시뮬레이션이 아닌 실측입니다. 측정일 2026-11-11, OpenRouter 경유 `google/gemini-3.8-flash`.**
> 측정은 사용자가 `npm run cache:probe -- --real`로 직접 실행했고, 이 문서는 그 결과를 정리한 것입니다.
> 아래에서 **"(원문 필요)"** 로 표시한 칸은 아직 원문 표가 이 저장소에 없어 비워 둔 곳입니다. 추정해서 채우지 않았습니다.

## 1. 실측 결과

사용자가 보고한 결론(원문 요약):

| 조건 | 결과 |
| --- | --- |
| 자동(암시적) 캐시, 약 11.5K토큰 동일 요청 반복 | **cached = 0** (길이를 키워도 동작하지 않음) |
| 명시적 캐시 `cache_control`, 약 1.75K토큰 | **cached = 0** (최소 길이 미달로 효과 없음) |
| 명시적 캐시 `cache_control`, 약 5.8K토큰 | **동작**. 첫 요청부터 `cached = cache_write = 5647` |

> 표를 채우려면 `npm run cache:probe -- --real`의 "실험 / usage 원문" 출력을 그대로 붙여 주세요.

### 비용 검산 (원문 `cost` 필요)

제공사가 준 `usage.cost`(실제 청구액)와 단가표 추정(`estCost`)을 맞춰 본다. 단가(2026-11-11 OpenRouter 확인, USD/1M): 입력 0.75, 출력 3.75, 캐시 읽기 0.075, 캐시 쓰기 0.041667.
추정식: `(입력 − 캐시읽기 − 캐시쓰기)×입력 + 캐시읽기×읽기 + 캐시쓰기×쓰기 + 출력×출력`.

- 주의: E5b에서 `cached = cache_write = 5647`이면 이 5,647토큰이 **읽기 단가와 쓰기 단가 중 무엇으로 청구됐는지** 위 식으로는 모호하다. 식은 `cached`와 `write`를 서로 다른 토큰으로 보고 `입력 − 캐시읽기 − 캐시쓰기`를 구하므로, 같은 토큰이 두 번 세어진 값이면 음수 방향으로 왜곡될 수 있다(코드는 0 미만으로 내려가지 않게 막아 두었다).
- 실제 `cost`가 있으면 "5647토큰을 읽기로 청구했는가 / 쓰기로 청구했는가 / 둘 다인가"를 역산할 수 있다 → **원문 `cost` 확인 후 결론**.

## 2. 판정

- **확인된 것**: 이 모델·경로에서 암시적 캐시는 11.5K에서도 0이다. 명시적 `cache_control`은 5.8K에서 동작하고 1.75K에서는 동작하지 않는다(문서의 4,096토큰 최소 길이와 일치).
- **아직 모르는 것**: 첫 요청부터 `cached = write`로 찍히는 것이 "실제 재사용"인지 "쓴 만큼을 매번 cached로 보고하는 것"인지. → **E6**이 가른다.
  - 앞부분이 서로 다른 약 5K 요청 2개를 각각 처음 보낸다. 둘 다 첫 요청부터 `cached>0`이면 **"매 요청 할인"** 방식(재사용이 없어도 할인이 붙음), 둘 다 0이면 **"재사용"** 방식(같은 접두사를 다시 보낼 때만 cached).
  - 실행: `npm run cache:probe -- --real --only E6` (2회, 각 약 5K토큰 입력).
- 따라서 `UsageLog`의 캐시 적중률(`cachedInputTokens`)은 E6 결과가 나올 때까지 "재사용 비율"로 해석하지 않는다. 비용은 `actualCost`(실제 청구액)가 기준이다.

## 3. 설계 (실제 호출 없이 구현·테스트만 했고, 기본값은 지금 동작 그대로)

E6 결과를 보고 기본값을 정한다. 지금은 아래 세 옵션 모두 **꺼져 있거나 기존 값**이다.

| 옵션 | 환경변수 | 기본값 | 내용 |
| --- | --- | --- | --- |
| 명시적 캐시 breakpoint | `CACHE_BREAKPOINT=1` | 꺼짐 | 조립기가 **현재 사용자 입력 직전의 마지막 안정 메시지**에 표시(`cacheBreakpoint`)를 붙이고, `OpenAiCompatAdapter`가 그 메시지의 content를 `[{type:"text", text, cache_control:{type:"ephemeral"}}]`로 바꿔 보낸다. Gemini는 **마지막 breakpoint만** 쓰므로 한 개만 붙인다. |
| 로어북 위치 | `LOREBOOK_POSITION` | `afterFixed` | `afterFixed`: 고정 블록·요약 바로 뒤(지금 동작). `beforeInput`: 최근 대화 뒤, 이번 입력 바로 앞. 로어북이 턴마다 바뀌어도 그 앞의 접두사(고정+요약+최근 대화)가 유지된다. `beforeInput`이면 breakpoint는 로어북이 아니라 **그 앞의 안정 메시지**에 붙는다. |
| 최소 길이 규칙 | `CACHE_MIN_TOKENS` | `4096` | breakpoint 앞부분이 이 값 미만이면 붙이지 않는다(E5: 1.75K에서 효과 없음). |

- **토큰 환산 주의**: `estimateTokens`는 글자당 1토큰이라 실제보다 크다(실측 약 0.55배: 고정 블록 추정 2,356 ↔ 실제 약 1.3K). 최소 길이 판정은 추정값에 `ESTIMATE_TO_REAL = 0.55`를 곱한 값으로 한다. 즉 추정 약 7.4K자 이상이어야 4,096토큰으로 본다. 모델·언어가 바뀌면 `cacheEstimateScale`(조립기 옵션)로 조정한다. 이 환산값은 한 번의 실측에서 나온 근사치이므로 첫 실사용 때 `blockTokens`와 제공사 `prompt_tokens`를 대조해 확인할 것.
- **전송 안전**: 내부 표시 필드는 `toWireMessage`가 항상 제거해 제공사로 새지 않는다(테스트로 고정). breakpoint 옵션이 꺼져 있으면 전송 본문은 이전과 동일하다.
- **한계**: 조립기는 세션 요약이 바뀌는 시점(`SUMMARY_EVERY`마다)에는 접두사가 달라지는 것을 막지 못한다. TTL은 5분 고정이고 갱신되지 않는다(문서). `session_id`는 아직 요청에 넣지 않는다(미결정).
- 효과 판단 전까지 `/admin`의 적중률 표시는 그대로 두었다.
